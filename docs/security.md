# 安全指南

## 安全最佳實踐

### 1. 環境變數管理

**重要：** 所有敏感信息必須使用環境變數，不要硬編碼在程式碼中。

- SECRET_KEY
- 資料庫密碼
- API 密鑰
- 郵件服務密碼

### 2. 輸入驗證

所有用戶輸入都必須驗證：使用 Django Form／Model 欄位約束與 ORM，不要自行拼接 SQL。

### 3. SQL 注入防護

Django ORM 自動防護 SQL 注入，但請注意：

- ✅ 使用 ORM 查詢
- ✅ 使用參數化查詢
- ❌ 不要使用字符串拼接構建 SQL

### 4. XSS 防護

- 使用 `{{ variable|escape }}` 或 `{{ variable|safe }}`（僅在確定安全時）
- 富文本內容使用 `|safe` 但要確保內容來源可信

### 5. CSRF 防護

- 所有 POST 請求必須包含 CSRF token
- 使用 `{% csrf_token %}` 在表單中
- AJAX 請求需要設置 CSRF token header

### 6. 權限檢查

- 使用 `@login_required` 裝飾器
- 檢查用戶是否有權限訪問資源
- 不要信任客戶端傳來的用戶 ID

### 7. 文件上傳安全

- 驗證文件類型
- 驗證文件大小
- 重命名上傳的文件
- 存儲在安全的位置

### 8. 密碼安全

- 使用 Django 的密碼驗證器
- 密碼必須加密存儲（Django 自動處理）
- 不要記錄或顯示明文密碼

### 9. Session 安全

- 使用 HTTPS（生產環境）
- 設置適當的 Session 過期時間
- 使用安全的 Cookie 設定

### 10. 日誌安全

- 不要在日誌中記錄敏感信息（密碼、信用卡號等）
- 定期清理日誌文件
- 限制日誌文件訪問權限

## 安全檢查清單

部署前請確認：

- [ ] DEBUG = False
- [ ] SECRET_KEY 使用環境變數
- [ ] ALLOWED_HOSTS 已設置
- [ ] 資料庫密碼使用環境變數
- [ ] HTTPS 已啟用
- [ ] CSRF 保護已啟用
- [ ] XSS 防護已啟用
- [ ] 文件上傳已驗證
- [ ] 權限檢查已實施
- [ ] 日誌不包含敏感信息

## 報告安全問題

如果發現安全漏洞，請立即聯繫開發團隊。
